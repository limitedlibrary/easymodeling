# 簡単モデリング

設定を変えるだけでキャラクターの形と配色を調整し、Blenderへ持ち帰れるブラウザ用ツール。

## 今回のゴール

標準のちびキャラを使って「設定でどんな変化を作れるか」を確認できる操作可能な試作を完成させる。高品質なキャラクター制作全般を初版で実現することは目標にしない。

## シリーズの方針

- 単体で完結し、ユーザーによる素材の事前準備を必要としない。
- 将来は他の簡単シリーズや自作素材と任意に組み合わせられる。
- Blenderで続きを編集できる書き出し経路を維持する。

## 初版の仕様

- HTML/JavaScriptベースのブラウザツール。日本語UI。PCを優先し、狭い画面でも設定を操作できる配置にする。
- プログラム生成の標準ちびキャラを同梱する。頭・顔・髪・胴体・腕・脚を備える。
- 頭の大きさ、胴体の長さ・幅、腕と脚の長さ、髪の長さをスライダーで調整する。
- 肌・髪・服の色を変更する。
- 変更は即座に3Dへ反映する。接続位置を追従させ、足が床に接するようにする。
- 視点回転・ズーム・正面へ戻す操作と、設定初期化を用意する。
- 編集設定をバージョン付きJSONで保存・読み込みできる。不正な入力では現在のモデルを壊さずエラーを表示する。
- キャラクターのみをGLBに出力する。床・背景・確認用ライトは含めない。
- パーツ名と配色を保持し、Blenderで個別編集できる構造にする。
- 外部ライブラリを使う場合はバージョンを固定し、必要なライセンス表示を残す。起動に通信が必要ならREADMEに明記する。

## 今回の対象外

ボーン、ウェイト、アニメーション、自由な頂点編集、外部モデル読み込み、多数の髪・衣装プリセット。GLBは形状編集用であり、そのまま自然に動かせるモデルを保証しない。

## 完了条件

1. 素材を追加せず標準キャラが表示される。
2. 各設定の変化が分かり、最小・最大の設定で接続が大きく破綻しない。
3. 設定初期化、JSON保存と復元が動く。
4. GLBを書き出せる。可能ならBlenderで形状・色・パーツ分離を確認する。未検証なら明記する。
5. 起動方法・確認結果・制限事項をREADMEとPRに残す。

## 起動方法

1. このリポジトリをクローンまたはダウンロードする。
2. リポジトリ直下で簡易HTTPサーバーを起動する（ES Modulesをブラウザで読み込むため、`file://`では動作しません）。
   ```bash
   python3 -m http.server 8000
   ```
   または `npx serve .` など、任意の静的ファイルサーバーで構いません。
3. ブラウザで `http://localhost:8000/index.html` を開く。
4. 起動後の通信は不要です。Three.js r0.160.0（本体・OrbitControls・GLTFExporter）を `vendor/` 以下に同梱しており、CDNへのアクセスは発生しません（ライセンスは `vendor/three/LICENSE` を参照）。

## 実装状況（試作・PR #1対応）

Issue #1 の実装範囲に対応した操作可能な試作が `index.html` / `style.css` / `app.js` / `character.js` にあります。

- 素材の事前準備なしで表示される標準ちびキャラ（頭・顔・髪・胴体・腕・脚をプログラムで生成）
- 頭の大きさ、胴体の長さ・幅、腕・脚の長さ、髪の長さをスライダーで調整し、即座に3Dへ反映
- 肌・髪・服の色をカラーピッカーで変更
- 脚を起点に下から積み上げて再構築する方式のため、スライダーをどう動かしても足は常に床（y=0）に接地し、各パーツの接続位置も自動的に追従する
- 視点回転・ズーム用のボタン（マウスドラッグ／ホイールによる操作にも対応）と、正面へ戻すボタン
- 設定初期化ボタン
- バージョン付きJSON（`version`, `parameters`, `colors`）の保存・読み込み。範囲外の値や壊れたJSONを読み込んだ場合は、現在のモデルを変更せずにエラーメッセージを表示する
- キャラクターのみ（床・背景・確認用ライトを含まない）のGLB書き出し。パーツ名（`Head` / `Torso` / `Arm_L` / `Leg_R` / `Hair_Cap` など）とマテリアル名（`Skin` / `Hair` / `Clothes` / `FaceDetail`）を保持
- 日本語UI。PC優先のレイアウトだが、幅900px以下では操作パネルが縦積みになり、狭い画面でも設定を操作できる

### 確認結果

Playwright（Chromium）でブラウザ操作を自動化して確認しました（Blenderでの確認は未検証です。下記「制限事項・未解決事項」を参照）。

1. 標準ちびキャラが追加素材なしで表示されることを確認。
2. 頭の大きさ・胴体の長さ／幅・腕の長さ・脚の長さ・髪の長さの各スライダーについて、最小値・最大値および複数を同時に最大/最小付近にした組み合わせで表示を確認。いずれの場合も頭・胴体・腕・脚・髪の接続が大きく破綻せず、足は常に床に接地していることを画面キャプチャで確認。
3. 「設定を初期化」で既定値に戻ることを確認。JSON保存→初期化→保存したJSONの読み込みで、スライダー値・配色が保存前の値に正しく復元される往復（ラウンドトリップ）を確認。
4. 不正な入力の検証：(a) 構文的に壊れたJSONファイル、(b) スライダー範囲外の数値を含むJSON、のいずれを読み込ませても、エラーメッセージが表示され、読み込み前のモデル・設定値が変更されないことを確認。
5. GLB書き出しを実行し、ダウンロードされたファイルがglTFバイナリ（先頭4バイトが `glTF`）として正しい構造であること、JSONチャンクを解析してノード名（`Head`, `Torso`, `Arm_L`, `Leg_R`, `Hair_Tail` 等）とマテリアル名（`Skin`, `Hair`, `Clothes`, `FaceDetail`）がパーツごとに保持されていること、床・背景・確認用ライトに相当するノードが含まれていないこと（シーン直下のノードはキャラクタールートのみ）を確認。**Blenderでの実際の取り込み・形状/色/パーツ分離の確認は、本環境にBlenderがないため未検証です。**
6. 視点回転・ズーム・正面に戻すボタン、およびマウスドラッグ／ホイールでの操作が機能することを確認。
7. ブラウザのコンソールエラーが発生しないことを確認（幅480pxの狭い画面でもレイアウトが縦積みになり操作可能であることも確認）。

### 制限事項・未解決事項

- Blenderでの実取り込み確認は未検証です。GLBの構造（ノード名・マテリアル名・色・床/ライトを含まないこと）はglTFの中身を直接解析して確認済みですが、Blender上での見た目・パーツ分離・編集可否は未確認のため、確認いただけると助かります。
- 対応していないGLB変種（Draco圧縮やテクスチャ埋め込みなど）は意図的に使用せず、色は各パーツのベースカラー（`pbrMetallicRoughness.baseColorFactor`）のみで表現しています。
- 髪型・服装のバリエーションは持たず、Issue記載の対象外範囲（ボーン・ウェイト・アニメーション・自由な頂点編集・外部モデル読み込み・多数のプリセット）は実装していません。
- モバイル実機でのタッチ操作（ピンチズーム等）は未検証です（狭い画面でのレイアウト崩れがないことはブラウザ幅480pxのスクリーンショットで確認済みです）。
